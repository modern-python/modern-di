# Design: Stop every container being a reference cycle

## Summary

`Container.__init__` puts the container into its own `_scope_map`. That self-reference makes
every container cyclic garbage, so no container is ever freed by reference counting — each one
waits for a generational GC pass. Building the map from the parent instead removes the cycle.
`find_container` never reads the self-entry, so the resolution hot path is untouched.

## Motivation

From the [audit](../audits/2026-07-27-container-reference-cycles-report.md), measured on an
Apple M4 / CPython 3.14.6:

- Each closed container leaves **8 objects** that reference counting cannot reclaim; 1000
  closed REQUEST children leave 7992.
- On a 100-request benchmark batch, disabling the GC leaves the median unchanged (190.9 →
  193.5 µs) but collapses within-run dispersion from **51.4% to 3.5%** IQR. The tail is
  entirely GC.
- The same tail makes modern-di's published C4 cell the least stable measurement on the
  performance page, and makes a median of single measurements understate the true amortized
  per-request cost by ~20% (1.86 µs read against a 2.33 µs true cost).

A container per request means cyclic garbage per request, in every application using REQUEST
scope — the framework's primary use case. It does not leak, but it converts a steady cost into
a periodic pause, which is what a production service feels as latency variance.

## Design

`modern_di/container.py:121-123` currently seeds the map with the container itself:

```python
self._scope_map = {**parent_container._scope_map, scope: self} if parent_container else {scope: self}
```

Seed it from the parent instead:

```python
self._scope_map = {**parent_container._scope_map, parent_container.scope: parent_container} if parent_container else {}
```

A REQUEST child then holds `{APP: root}` instead of `{APP: root, REQUEST: self}`. Every
container still reaches every ancestor, no container reaches itself, and the object graph
becomes acyclic — so a child is freed the moment it goes out of scope.

This is safe because `find_container` (`:160-168`) already short-circuits before the lookup:

```python
if scope == self.scope:
    return self
target = self._scope_map.get(scope)
```

The self-entry is dead weight on the resolution path — never read. Removing it costs no branch
and adds none.

**Prototyped and reverted on the branch that found it:** cross-scope resolution still works,
1000 closed children leave 0 objects for the collector (down from 7992), and 448 of 449 tests
pass untouched.

The single failure is `tests/test_container.py::test_private_lock_and_scope_map_back_the_machinery`,
which asserts the map contains the self-entry. It encodes exactly the behaviour being changed,
so it is updated to assert the new contract — a container's map holds its ancestors, not itself
— rather than worked around.

## Non-goals

- Changing `find_container`'s signature or semantics — it already behaves correctly.
- Removing the deprecated `scope_map` property. Its contents change as a consequence; that is
  in-scope. Its removal is not.
- Adding `__weakref__` to `Container.__slots__`. Tempting for observability, but it grows every
  container for a diagnostic need.
- Chasing other GC pressure. This change addresses the self-reference only; whether any cyclic
  garbage remains per request is a question for the verification below to answer, not an open
  commitment.

## Testing

TDD, failing test first. The failing test asserts the property that matters — that a closed
child is reclaimed without the cycle collector — not merely that a dict changed shape:

```python
def test_closed_child_is_freed_without_the_cycle_collector() -> None:
    app = Container(scope=Scope.APP)
    app.open()
    gc.collect()
    gc.disable()
    try:
        child = app.build_child_container(scope=Scope.REQUEST)
        child.open()
        child.close_sync()
        del child
        assert gc.collect() == 0  # nothing left that only the collector could reclaim
    finally:
        gc.enable()
```

That test fails today (returns 8) and passes after the change.

Then: update `test_private_lock_and_scope_map_back_the_machinery` to the new contract; confirm
cross-scope resolution across a depth-3 chain; and re-run `just bench` — `g5_cross_scope` and
`g6_build_child_container` are the guard scenarios this could plausibly move, and neither
should regress.

`just test-ci`, `just lint-ci`.

## Risk

- **A consumer reads `scope_map` and depends on the self-entry.** The property is already
  deprecated and warns on access, so the exposure is small, but the contents change is a real
  behaviour change for anyone who ignored the warning. Mitigation: state it in the release
  notes; the deprecation warning already discourages the access.
- **The measured variance win may not reproduce on other platforms or CPython builds.** The
  51.4% → 3.5% figure is one machine. The correctness of removing a pointless self-reference
  does not depend on it, but the release notes should not promise a specific latency
  improvement.
- **Free-threaded builds** collect differently; the change removes a cycle rather than adding
  one, so the direction is safe, but `architecture/concurrency.md` should be checked for any
  claim this affects.
