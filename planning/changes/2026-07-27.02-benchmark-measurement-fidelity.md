# Design: Make the benchmarks measure what they claim

## Summary

The [benchmark fidelity audit](../audits/2026-07-27-benchmark-fidelity-audit-report.md)
found nine defects. Nothing is fabricated — the published ratios reproduce — but
C4 and G7 measure asyncio rather than DI, two per-framework asymmetries run in
modern-di's favour, and the published table cannot be regenerated from the repo.
This change fixes all nine and re-measures
`docs/introduction/performance.md` on the corrected suite.

## Motivation

From the audit, on the audit machine:

- A modern-di request cycle costs **2.04 µs**; C4 and G7 report **29.8 µs**
  because each times one `loop.run_until_complete` entry, whose empty-coroutine
  floor is **27.4 µs**. The DI signal is 6.8% of the number. The published
  "level with dishka (1.00)" is that floor, not a tie — in the audit run
  modern-di and dishka reported medians identical to the nanosecond.
- G7 cannot function as a guard: a 2x teardown regression moves it ~7%, under
  the workflow's 150% alert threshold.
- C4 builds dependency-injector's container inside the timed call (29% of its
  number); C1–C3 time modern-di by reference against dishka/wireup by type
  (+11% when levelled).

## Design

**Fix 1 — amortize the loop (C4, G7).** The timed callable performs `K = 100`
request cycles inside a single `run_until_complete`, identically for all five
frameworks and for G7. Measured on the audit machine, that moves the floor from
92% of the number to **15.3%** (batch 200.3 µs, floor control 30.6 µs,
per-request 2.00 µs against the 2.04 µs measured directly). The reported number
is a batch; the report script divides by `K` to publish per-request, and
`benchmarks/README.md` states `K` and the division.

```python
_BATCH = 100


async def _batch() -> list[Connection]:
    return [await _one_request() for _ in range(_BATCH)]


conns = benchmark(lambda: loop.run_until_complete(_batch()))
```

All nine fixes ship as one change because the page must be re-measured once,
after the last of them lands — splitting them means re-publishing the table
several times with numbers that are each wrong in a different way.

A companion control, `test_g7c_event_loop_floor_control`, times an empty
coroutine over the same `K` so the residual floor is visible in every run rather
than asserted — the same device the concurrency file already uses for its
pure-compute control.

**Fix 2 — hoist per-call construction (C4).** `LifecycleContainer()` moves to
setup for dependency-injector, matching the other four; `init_resources` /
`shutdown_resources` still run per iteration.

**Fix 3 — 3.x lifecycle in the comparative tier.** `test_modern_di.py` calls
`open()` on the root and `req.open()` per request, matching the guard tier and
the documented idiom.

**Fix 4 — level the lookup axis.** C1–C3 split into by-reference and by-type
variants for modern-di, published as **two tables** rather than one: by-reference
against that-depends and dependency-injector, by-type against dishka and wireup
(C4, unsplit, keeps its own table against all four). A single table with four
rival columns would fill half of every split row with `n/a`; three tables make
every published cell a real comparison.

**Fix 5 — disclose the lock axis.** A README row and a page sentence: dishka
defaults to a per-`get()` `_thread.lock`, modern-di's cached read is lock-free,
both run at their defaults. No code change.

**Fix 6 — generate the published table.** `benchmarks/comparative/report.py`
plus `just bench-report`: runs the suite five times with
`--benchmark-json`, reduces each cell to a median **and its across-run IQR** —
ratios paired within each run, since one run measures both sides under the same
machine state — and prints the exact markdown the page publishes. Comparative tests gain framework suffixes
(`test_c1_transient_dishka`) so raw pytest output is readable too. The page
cites `just bench-report` as the command that produced it.

**Fix 7 — close the coverage gaps.** Guard tier gains `G16` (warm by-type
`resolve(SomeType)`) and `G17` (the same against a **200-provider** registry, so
`find_provider` is guarded at realistic scale).

**Fix 8 — equalize subject classes.** The comparative tier moves to plain
`__init__` classes for every framework including modern-di. The guard tier keeps
`dataclass(slots=True)`: it only ever compares modern-di to itself, and changing
it would break the CI baseline for no fidelity gain.

**Fix 9 — complete the C5 caveat.** Note that dishka's C5 includes per-call
provider registration (13%) that modern-di hoists to import time.

**Fix 10 (added in review) — level the `iterations` axis.** pytest-benchmark
auto-calibrates `iterations` per benchmark per run, which left several C1/C3
cells at `iterations=1` — carrying a whole per-round timer pair and snapped to
the platform timer's ~42 ns grid — while others ran at 20-100. A published ratio
must not divide a grid-snapped number by an unsnapped one. C1-C4 move to
`benchmark.pedantic` at a shape pinned identically in all five files (C1-C3
`rounds=200, iterations=1000`; C4 `rounds=100, iterations=3`), with
`warmup_rounds=1` standing in for the warm-up calibration used to provide.
`tests/test_bench_report.py` parses the five sources and fails if any published
scenario drops off the pinned shape or the numbers drift apart.

## Non-goals

- Bumping rival pins — moves ratios for unrelated reasons; its own change.
- Publishing C5/C6 on the page — a content expansion, already deferred by
  [`2026-07-27.01`](2026-07-27.01-refresh-performance-numbers.md).
- Making the CI benchmark job gating — GitHub-hosted runners stay too noisy.
- Memory or allocation measurement.

## Testing

- `just bench` — guard tier green; `g7c` control confirms the residual floor is
  <20% of the G7 batch number (15.3% measured at `K = 100`; raising `K` to 500
  would reach 4.3% at 5x the wall-clock per round).
- `just bench-report` — emits the markdown table; its modern-di C4 per-request
  figure must land near the 2 µs the audit measured directly, not near 29 µs.
- `just test-ci`, `just lint-ci`, `just check-planning`, `mkdocs build --strict`.

## Risk

- **The C4 and G7 baselines break.** Batching changes both scale and meaning, so
  `github-action-benchmark` will see a step change. Mitigated by renaming the
  batched scenarios so the alert baseline restarts clean rather than firing a
  false regression.
- **Published verdicts may move.** Fixes 3, 4, and 8 all cost modern-di
  slightly; fixes 1 and 2 favour it. Direction per cell is not predictable in
  advance, and the change ships whatever the corrected suite reports.
- **`K = 100` may under-amortize on slower machines.** The `g7c` control makes
  that visible in the run rather than silent; raising `K` is a one-line change.
