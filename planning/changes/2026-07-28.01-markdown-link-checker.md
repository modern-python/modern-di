# Design: A link checker for the docs mkdocs cannot see

## Summary

`planning/links.py` validates every relative Markdown link and heading anchor in
the repository and runs as part of `just lint-ci`. It exists because
`mkdocs build --strict` only processes `docs/`: `architecture/` — the truth home
every behavioral change is promoted into — sits outside `docs_dir` and is read on
GitHub, so a rotted link there is invisible to CI. Its first run found 11 broken
links, all in `planning/`; those are fixed here.

The checker is **not modern-di code**. It was contributed upstream to
`lesnik512/planning-convention` and arrives here as part of applying that
convention's **2.1.0** release, alongside `planning/index.py`. This bundle records
the apply and the link fixes; the checker's own tests live upstream.

## Motivation

Anchors in `architecture/` broke **three separate times in one week**, each caught
only by a human re-deriving slugs by hand:

- a heading renamed to `## Enabling validation — monotone at construction…` while
  two links still pointed at `#enabling-validation`;
- the same heading's em dash producing *different* anchors under GitHub and
  python-markdown, so a link could resolve on the published site and 404 on GitHub;
- `docs/providers/factories.md` pointing into `comparison.md` at an anchor that
  worked under mkdocs and not on GitHub.

None of these were catchable by the existing gates. A change that alters a
capability must update `architecture/<capability>.md` in the same PR, so this is a
rot vector aimed squarely at the files the repo treats as authoritative.

## What the apply carries

Per the convention's `APPLY.md`, an UPDATE from 2.0.0 to 2.1.0 is:

- **§1 verbatim copy** — `links.py` → `planning/links.py`, byte-identical to the
  canonical file. Local edits to it are intentionally discarded; changes belong
  upstream.
- **§3 judgment merge** — the `check-links` recipe plus a `planning/links.py` step
  in `lint-ci`.
- **§2 prose** — the `## Conventions` blockquote now names `just check-links` and
  refers to `.convention-version` as inline code rather than a link.
- `planning/.convention-version` → `2.1.0`.

## How it works

It walks every `*.md` outside `.git`, `.venv`, `.superpowers`, `site` and the
caches — 261 files here, across `planning/`, `docs/` and `architecture/` — and for
each inline link that is not external it checks the target file exists and, when
the link carries a `#fragment`, that the fragment matches a heading in that file.
A bare `#fragment` is checked against its own file's headings, since a same-page
link rots exactly like a cross-page one. It finds its own root by walking up to
`.git`, because it has two homes: the canonical repo's root and a consumer's
`planning/`.

**Slugs follow GitHub's algorithm**, because every file here is read on GitHub,
including the ones mkdocs also publishes. Where the two renderers disagree — a
heading containing ` — ` yields `a--b` on GitHub and `a-b` under python-markdown —
the checker demands the GitHub form and the docstring says the fix is to keep em
dashes out of headings you link to, rather than teaching it both dialects.

## Non-goals

- **External URLs are not fetched.** This checks internal consistency; a network
  check belongs in a scheduled job, not a lint gate.
- **No mkdocs-dialect mode.** Where the two sluggers disagree the answer is to
  change the heading, which the docstring states.

## Testing

`just lint-ci` and `just check-links` clean; `links: OK` over all 261 files.

The checker's unit tests live upstream with the code — 20 tests for `links.py` in
`lesnik512/planning-convention`, part of a suite that repo holds at 100% coverage.
Nothing here imports `planning/links.py`, so it is outside this repo's coverage
gate, matching `planning/index.py`; both are exercised by running in `lint-ci`.

It was verified to *bite* in this repo, by reintroducing the failures it exists
for and confirming each is reported:

- a real link's anchor altered (`validation.md#what-validate-checks` →
  `…-WRONG`) → reported at `architecture/containers.md:135`;
- an em dash added to a linked heading, leaving every existing link pointing at the
  old slug → reported at the same site, which is exactly the class that broke three
  times;
- a link to a non-existent file → reported.

Each was restored and the tree returns to `links: OK`. An earlier attempt at the
first case edited a string that did not exist in the file, so the checker
"passed" a break that was never made — the test was vacuous, and the retry uses a
link confirmed present first.

## Risk

- **11 links in `planning/` were rewritten.** Ten were wrong relative depths
  (`../../../audits/…` from a file two levels deep) — unambiguous typos whose intent
  is clear, and fixing them makes an immutable record navigable rather than
  rewriting it. The eleventh linked to `./plan.md`, a file that never existed
  because plans are ephemeral by convention; that sentence now points at the
  convention instead of a dead path.
- **False positives would block CI.** Two classes surfaced while the checker was
  being written upstream — underscores must survive slugification (this repo's
  headings are full of identifiers like `container_provider`), and heading
  extraction must not strip inline spans the way link extraction does. Both are
  fixed and regression-tested upstream. Anything new surfaces as a lint failure
  with a file:line, not a silent pass.
